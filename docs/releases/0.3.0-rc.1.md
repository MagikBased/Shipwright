# JP Assist Learning Platform 0.3.0-rc.1

This is a local, production-shaped release candidate. It is not a public hosted
service. HTTP API `/v1` and SQLite schema `9` are the compatibility boundaries.

## Highlights

- Private accounts with verification, recovery, notification preferences,
  device/session revocation, exports, per-game clearing, and deletion.
- Searchable multi-game vocabulary, annotations, activity, goals, deterministic
  FSRS-6 reviews, and explicit JP Assist/Anki scheduling ownership.
- Retry-safe mod synchronization and stable Anki card/review-history identity.
- Responsive, keyboard-accessible account UI qualified in Chromium and Firefox.
- Production-shaped HTTPS staging with Mailpit, Prometheus, Grafana, structured
  correlation logs, automatic backups, hourly reminder/retention maintenance,
  and isolated restore drills.
- Supply-chain SBOM, secret/dependency scans, privacy-boundary tests, load
  qualification, and migration rollback rehearsal.

## Database and upgrade notes

Schema `9` adds independent public website-session IDs, last-seen timestamps,
and privacy-minimal user-agent labels. Existing schema-8 sessions receive
generated public IDs and preserve their creation time as initial last-seen
time. This candidate also adds indexes for account vocabulary joins; they are
created idempotently without changing logical data.

Before upgrading, run the current smoke/restore drill, make an off-host backup,
and record its checksum and the current image digest. Startup performs the
forward migration. Rollback requires the matching pre-upgrade backup and older
image; follow `docs/LEARNING_PLATFORM_OPERATIONS.md` rather than running an
older binary against schema 9.

## Known limitations

- Hosting, DNS, public registration, real transactional email, external uptime
  monitoring, and organizational incident contacts are deliberately absent.
- The SQLite topology uses one application worker and is not a multi-replica
  deployment.
- Mailpit captures local staging email; a public operator must select and
  validate a provider.
- Chromium owns visual snapshots. Firefox passes functional/accessibility
  acceptance. WebKit is unqualified because its Playwright fallback cannot
  launch on the current Mint host without unavailable `libavif13`.
- Anki review-history import requires an AnkiConnect build supporting
  `getReviewsOfCards`; stable card synchronization remains available without it.
- Local Caddy HTTPS uses a development certificate and may require a browser
  trust exception.

## Validation summary

- 52 service/API/privacy/migration tests.
- 15 Chromium browser scenarios and 14 Firefox scenarios; the skipped Firefox
  case is Chromium-only pixel comparison.
- Cross-component Anki package and stable-ID acceptance.
- 8,000 unique words and dictionary entries from eight concurrent devices: no
  failed uploads, retry deduplication preserved, 440 ms ingest p95 and 445 ms
  account-query p95 on the qualification host, below the 2,000/1,500 ms gates.
- 5,000-word schema-8 forward, preserved-schema rollback, and reapply with no
  logical row-count change.
- Production image smoke, SBOM, and no unresolved high/critical vulnerability.
